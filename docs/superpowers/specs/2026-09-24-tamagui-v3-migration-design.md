# Tamagui v3 Migration Design

## Goal

Upgrade Cyclone UI from Tamagui 2.7.7 to Tamagui v3 while preserving the existing custom tokens, generated themes, public component APIs, and web/native behavior.

## Scope and constraints

- Upgrade the root pnpm catalog and lockfile to a mutually compatible Tamagui v3 release.
- Keep the existing custom token values, media configuration, fonts, animations, and generated theme vocabulary. This is not a v5-to-v6 design-system migration.
- Convert legacy Tamagui style syntax (`$` tokens, pseudo-style props, media/platform/theme/group objects) to v3 flat values.
- Preserve deliberate raw-CSS, `useTheme().val`, `getTokenValue`, and prop-order escape hatches.
- Do not edit `node_modules`, vendored code, or the external Razorwind package in this repository.
- Preserve all pre-existing dirty skill files and limit staging to migration-owned files.

## Current ownership and migration boundary

`packages/themes/src/tamagui/config.ts` is generated by `@razorwind/tamagui`, configured in `razorwind.config.ts`, with supplemental consumer configuration in `packages/themes/src/tamagui/default-config.ts`. The generated file currently imports Tamagui v2 APIs (`@tamagui/config/v5-motion` and `@tamagui/theme-builder`).

Cyclone UI owns the Razorwind integration and its input configuration, but it does not own the generator implementation. Before updating dependencies, the migration must establish that the installed `@razorwind/tamagui` version can generate a valid v3 config while retaining this repository's semantic themes. If it cannot, the work pauses for an upstream Razorwind fix; no generated output will be hand-patched.

## Architecture

The migration proceeds in dependency order:

1. Make the configuration generator and generated config v3-compatible without changing resolved design values.
2. Update the package catalog and lockfile as one consistent dependency graph.
3. Run the Tamagui flat-values codemod report across `components`, `packages`, `apps`, and `tools`; apply only mechanically safe edits.
4. Manually migrate remaining shared primitives and their public prop types before leaf components. Keep `exitStyle` where shared/web animation behavior requires it.
5. Add editor/CI checks for valid v3 flat values, then validate builds and rendered Storybook behavior.

## Source inventory

- Tamagui catalog: `pnpm-workspace.yaml` contains the v2.7.7 Tamagui package catalog.
- Config owner: `packages/themes/src/tamagui/config.ts`, generated through `razorwind.config.ts` and `packages/themes/src/tamagui/default-config.ts`.
- Legacy surface: 42 component/source files use pseudo-style, group, platform, or presence condition objects. Shared owners include Button, Input, Field, Checkbox, Switch, RadioGroup, Select, Sheet, Dialog, Popover, Tabs, Table, and FilePicker.
- No fractional `$1.5`-style token literals were found in the source scan, reducing one common manual-migration class.
- Escape hatches include raw CSS custom-property usage in CodeBlock and SelectItems, and Theme wrappers that must remain theme-only unless an actual inline-style warning identifies a source owner.

## Flat-value conversion rules

Quoted token values lose the dollar prefix: `bg="$surfaceElevated"` becomes `bg="surfaceElevated"`. Conditional styles move into the target property's string: `hoverStyle={{ borderColor: "$accentHover" }}` becomes `borderColor="hover:accentHover"`. Named group states move to `group-hover/name:`; group size queries additionally require the declaring ancestor to own a matching `container` name.

The codemod report is a gate rather than a best-effort aid. Every unresolved entry receives a config-aware manual decision. Dynamic style values are lifted per property without reordering spreads. Composite shadows/transforms and shared/web `exitStyle` paths are reviewed manually rather than mechanically flattened.

## Verification

The migration has separate proof layers:

1. Generated config: token/theme snapshot or direct assertions establish that representative light/dark semantic values, media keys, fonts, and animations match the pre-upgrade configuration.
2. Static migration: `npx tamagui check`, a final codemod report with no unresolved legacy sites, focused type/build targets, formatting, and `git diff --check`.
3. Web runtime: Storybook checks cover light/dark, responsive group/container behavior, hover/press/focus styles, Dialog/Popover-to-Sheet adaptation, and animated enter/exit states.
4. Native runtime: where a native runner is available, validate a theme-value consumer and Sheet keyboard/safe-area/drag behavior. Web proof does not substitute for native proof.

## Out of scope

- Config v6 / Tailwind scale adoption.
- Token-scale or palette redesign.
- Changes to public component APIs unrelated to v3 compatibility.
- Patching any external Storm ecosystem package.

## Upstream contingency

If `@razorwind/tamagui` cannot emit v3-compatible imports/configuration, the required upstream change belongs in `storm-software/razorwind`.

**Target repository:** storm-software/razorwind  
**Package(s):** `@razorwind/tamagui`  
**Problem:** Generated Tamagui configuration targets v2 APIs, preventing a consumer that owns custom theme inputs from upgrading to Tamagui v3.  
**Root cause:** `@razorwind/tamagui@0.0.74` emits `createThemes` from
`@tamagui/theme-builder`, but the current Tamagui v3 beta family has no matching
`@tamagui/theme-builder` beta release (the available package remains 2.7.7).
Tamagui's supported v3 v5-checkpoint import is `createThemes` from
`@tamagui/config/v5`; retaining the generated external builder import would
split the dependency graph across incompatible generations.  
**Proposed changes:**
- Generator's Tamagui config template — emit `createThemes` from
  `@tamagui/config/v5` for v3-compatible generated configs, while retaining
  the existing custom token/theme values unchanged.
- Generator tests — generate a custom color/theme fixture, compile it against Tamagui v3, and assert representative resolved theme/token values.
**Verification:** Run the generator fixture, Tamagui config validation, and a consumer build against the generated config.  
**Cyclone UI impact:** Regenerating `packages/themes/src/tamagui/config.ts` becomes a supported v3 operation instead of a local, unmaintainable patch.
